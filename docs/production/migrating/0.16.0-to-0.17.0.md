# 0.16.0 to 0.17.0

Compile breaks first, then behaviour. This page is started with the metrics
step; the later steps of the release are added below it.

### Compile breaks

- **`AuthnMetrics` is gone: "cannot find trait `AuthnMetrics`", "no method
  named `with_metrics` takes this argument".** The one trait is replaced by
  one trait per concern, and `with_metrics` takes a `MetricSinks` instead of
  an implementor. Move each method of your `impl AuthnMetrics for X` under the
  trait of its concern, and implement only the concerns you export:

  | Old method | New trait |
  |---|---|
  | `auth_attempt`, `auth_success`, `auth_failure`, `account_locked` | `AuthFlowMetrics` |
  | `factor_attempt`, `factor_success`, `factor_failure`, `factor_counter_store_outage`, `attempt_throttled`, `recovery_codes_under_previous_pepper` | `FactorMetrics` |
  | `session_created`, `session_invalidated`, `session_binding_mismatch` | `SessionMetrics` |
  | `rate_limit_allowed`, `rate_limit_rejected` | `RequestGuardMetrics` |
  | `authz_cache_hit`, `_miss`, `_eviction`, `_invalidation` and their batched forms | `AuthzCacheMetrics` |
  | `audit_store_outage`, `audit_event_shed` | `AuditMetrics` |

  Then wire the exporter. A type that implements every concern is wired to all
  of them at once, and one that implements some is wired to those:

  ```rust,ignore
  // before
  AuthnService::builder(identity, factors).with_metrics(MyMetrics::new())
  // after, all concerns (add `impl X for MyMetrics {}` for each you skip)
  let sinks = MetricSinks::all(Arc::new(MyMetrics::new()));
  AuthnService::builder(identity, factors).with_metrics(sinks.clone())
  // after, some concerns
  let sinks = MetricSinks::noop().with_auth_flow(mine.clone()).with_session(mine);
  ```

  `SessionLayer`, `RateLimitLayer` and `CsrfLayer` take the same `MetricSinks`
  in `with_metrics`. `EntityCache::flush_metrics` takes a
  `&dyn AuthzCacheMetrics`; pass `sinks.authz_cache()`. `NoopMetrics`
  implements every concern. The old trait is removed outright, with no
  forwarding facade: a facade would forbid implementing the new traits
  directly (coherence), and neither the platform nor nomos implemented it.
  The design and the metric-versus-event rule are on the
  [observability page](../observability.md).

- **`AuthnService::oauth_providers()` returns an `Arc` snapshot, and
  `provider_names()` returns owned names.** The registry is swapped whole when
  a provider is reloaded, so a reference into the service cannot be handed
  out. Call `oauth_providers()` again to see a later change; a
  `let names = service.oauth_providers().provider_names();` now compiles where
  it would have borrowed a temporary. Adopters that only call
  `.provider_count()` or `.provider_names()` in one expression change nothing.
- **`LdapProvider` has a new method, `check_reachable`, with a default that
  refuses.** Nothing on the login path calls it; `AuthnService::reload_ldap`
  does, and refuses a provider that cannot say whether its directory answers.
  A custom provider that wants to be reloaded overrides it (connect and
  unbind, or `Ok(())`). `LdapProviderConfig` and `MockLdapProvider` do.
- **`Fido2Provider` has a new required method, `relying_party_id()`.** A live
  reload compares it with the provider in force and refuses a change unless
  the caller acknowledges it. Add `fn relying_party_id(&self) -> &str` to a
  custom provider and return the id its ceremonies are bound to; an empty
  string means "unknown" and makes a reload to or from it need the
  acknowledgement. `DefaultFido2Provider::new(webauthn)` reads the id from the
  `Webauthn` it wraps, so code that uses it compiles unchanged.
  `MockFido2Provider` is no longer a unit struct: write
  `MockFido2Provider::new()` (or `::default()`) where a test wrote
  `MockFido2Provider`; it reports `localhost`, changed with
  `with_relying_party_id`.
  `BuiltProvider` gains the variant `Fido2AllowingRpIdChange`, and
  `ProviderReloadError` the variant `RpIdChanged`; both enums are
  non-exhaustive.
- **`ProviderRegistryMetrics` gains `provider_reloaded`, `provider_removed` and
  `provider_reload_refused`, each taking a `ProviderCategory`, and
  `fido2_rp_id_changed`,** all defaulted to nothing, so an implementor compiles
  unchanged.
- **`ValkeyReloadCoordinator` is available with `valkey`, not only
  `valkey-cache`,** and the coordinator types moved to `axess::reload`; the
  `axess::authz::reload` paths still resolve.

### Behaviour

- **New counters for what used to be a log line.** CSRF refusals
  (`RequestGuardMetrics::csrf_rejected`, also for the session layer's WebSocket
  Origin refusal), duplicate provider registrations
  (`ProviderRegistryMetrics::provider_duplicate_registration`), reads that
  needed a previous key (`RotationMetrics::encryption_key_fallback` and
  `fingerprint_key_fallback`), fingerprint backfills
  (`SessionMetrics::session_fingerprint_backfilled`) and `sid` map capacity
  evictions (`SessionMetrics::sid_map_evicted`). They fire only for a sink
  you wired; the log lines remain.
- **A duplicate OAuth provider name stops a debug build at `build()`**, not at
  the `with_oauth_provider` call that repeated it. A release build keeps
  serving, reports the duplicate to `ProviderRegistryMetrics` and logs it, as
  before.
- **Providers can be changed on a running service.** Nothing changes until you
  call `reload_oauth_provider`, `remove_oauth_provider`,
  `reload_tenant_oauth_provider`, `remove_tenant_oauth_provider`,
  `reload_fido2`, `remove_fido2`, `reload_ldap` or `remove_ldap`; see
  [live provider reload](../../authentication/live-provider-reload.md). A
  candidate is checked before the swap, within
  `with_provider_validation_timeout` (30 seconds by default), and a refusal
  leaves the previous provider in force.
- **`SessionCrypto::with_metrics(sinks.rotation())`** reports the use of the
  previous encryption key. Without it nothing is reported.
