# 0.15.0 to 0.16.0

Compile breaks first, then behaviour.

### Compile breaks

- **`factors_completed` is a list of `(FactorKind, DateTime<Utc>)` pairs**
  (`AuthState::Authenticated::factors_completed` and
  `AuthState::Authenticating::completed`). You will see "expected tuple,
  found `FactorKind`" where you build a state, and "no implementation for
  `FactorKind == (FactorKind, ..)`" where you compare one. Build entries as
  `(kind, time)`; read kinds with `.iter().map(|(kind, _)| kind)`, or ask
  `AuthState::factor_completed_at(&kind)` and
  `AuthSession::completed_factor_within(&kind, max_age, now)`.
- **`AuthEvent::factors_completed` is `Vec<(FactorKind, i64)>`** (epoch
  microseconds, like `event_time`), and
  `AuthEventBuilder::with_factors_completed(kind, completed_at)` takes the
  time. An audit store that writes events as JSON or rkyv writes the new
  shape.

- **`SessionLayer::new` takes three arguments; `no method named with_registry`.**
  `SessionLayer::new(store, key, registry)` takes the registry as an
  `Arc<dyn SessionRegistryHandle>` (`Arc::new(SessionRegistryAdapter(registry))`,
  or `MemorySessionRegistry::handle()`); move the argument of your old
  `.with_registry(..)` call there and delete the call. `try_new` takes it
  too. The layer then ends a revoked session on every route. If you really
  keep no registry, build with `SessionLayer::without_registry_insecure(store,
  key)`, which keeps the old behaviour (revocation reaches only routes behind
  the validator) and logs an error once at build.
- **`no rules expected the token ..` in `require_authz!`.** The three-argument
  form is removed: it trusted the stored session record alone. Add
  `validator = authn.session_validator()` as the fourth argument.

- **`with_max_session_age`, `with_max_impersonation_age` and the config
  builder's `max_authenticated_age` and `max_impersonation_age` take an
  `Option<Duration>`** ("expected `Option<Duration>`, found `Duration`"). Wrap
  the value in `Some(..)`; `None` lifts the cap.

- **`PasswordRules` has a new field, `breached_check: bool`** ("missing
  field `breached_check`" where you build the rules without
  `..PasswordRules::default()`). Add `breached_check: true`, or spread the
  default. A stored row without the field reads as `true`. **`NewPasswordError`
  has two new variants, `Breached` and `BreachCheckUnavailable`**
  ("non-exhaustive patterns" where you match it); show each variant's
  `Display`, which is a sentence for the person.

- **`RefreshTokenConfig` has a new field and a new type for the previous
  pepper.** A struct literal without `..Default::default()` needs
  `allow_unkeyed_hashes: false`, and `previous_hash_pepper` is
  `Option<PreviousPepper>` ("expected `PreviousPepper`, found
  `Zeroizing<Vec<u8>>`"): write `Some(PreviousPepper::keyed(old_pepper))`.
  `RefreshTokenConfig::previous_pepper` answers `Option<Option<&[u8]>>`, the
  inner `None` being the unkeyed state.

- **`StatusDetail` has a required `cause: StatusCause`** ("missing field
  `cause`" at every struct literal). The cause says what put the account in
  its state: `Administrative` (an operator), `Verification` (awaiting
  activation), `Lockout` (a store that materialises a lockout as a state;
  axess itself never does), `Closure`, or `Other(key)` for your own. Build
  details with `StatusDetail::administrative(reason, since)`,
  `verification`, `lockout`, `closure` or `other(key, reason, since)`, and
  `.with_until(Some(t))` for a timed one, or add the field to the literal.
  `EntityState::is_locked()` is `is_suspended()`, since the old name read as
  the counter's lockout, which is never an `EntityState`.
  `EntityState::is_administratively_disabled()` and `can_self_recover()`
  read the cause, so an eligibility check (a self-service second-factor
  reset) asks them instead of `reason` or `until`. A row 0.15.0 stored
  through serde reads with `Other("unspecified")`, which neither question
  says yes to; a store with its own status columns writes the cause beside
  them so it reads back (the sqlite example adds a `status_cause` column).
  There is no opt-out: a detail always states a cause.

- **`panicked: session signing key is a single repeated byte` (or `session
  encryption key`, `factor secret encryption key`) at startup.**
  `SessionLayer::new`, `SessionCrypto::new` and `FactorSecretCipher::new` used
  to log a constant key (all zeros, `[7u8; 32]`) and carry on; they now refuse
  it. Load 32 random bytes from a secret store. A test that used a placeholder
  key calls `axess_core::testing::test_key(seed)` (or the type's
  `new_unchecked`, under the `testing` feature). `with_previous_key` on
  `SessionCrypto` and `FactorSecretCipher` panics on a constant key and on the
  current key, which took nothing out of use. `try_new` still returns the
  error where you want to handle it.

- **A `match` on `IssuanceError` is not exhaustive**: the enum has a new
  variant, `InvalidLifetime(LifetimeFault)`. Add an arm. It is returned by
  `LocalIdp::mint` for a `max_ttl` of zero or less, an `exp` that is not after
  the IdP clock's now, and an `nbf` after `exp`; those used to mint a token
  (or, with a cap, be reported as `LifetimeExceedsCap`). `LifetimeExceedsCap`
  now means only a lifetime over the cap.

- **`SessionStore::find_sessions_for_user` has no default.** Implement it on
  a hand-written store: list the user's live sessions, or return your own
  error saying the store cannot. Do not return an empty list for "cannot":
  callers read it as "no sessions".
- **`SqlStoreError::PayloadTooLarge` and `SqlStoreError::Unsupported`, and
  `ValkeyStoreError::Unsupported`, are new variants.** Add an arm to an
  exhaustive match. The SQL stores now refuse a payload over 64 KiB
  (`with_max_payload` sets another cap), and `find_sessions_for_user` on a SQL
  or Valkey store returns `Unsupported`; it used to return an empty list.
- **`SessionRegistryHandle::liveness` has no default.** A hand-written handle
  implements it: `Valid`, `Gone` when the registry answered that the session
  is not valid, `Unknown` when it could not answer.
- **`not all trait items implemented, missing: throttle_state,
  record_throttle_failure, clear_throttle`** on your `IdentityAuthnLog`.
  The throttle beside the lockout keeps its state in your store under a
  `ThrottleSubject` (tenant, user, client address): read it, add one
  failure atomically (an upsert) and forget it on a right guess, as the
  sqlite example's `login_throttle` table does; a decorator forwards all
  three. `FactorOutcome` and `AuthnError` have a new variant, `Throttled {
  retry_after }`; add an arm (answer it as a wrong credential, with
  `Retry-After`), and a `LockoutPolicy` literal without `..Default::default()`
  needs `throttle: Some(Throttle::default())` or `None`.

- **`not all trait items implemented, missing: revoke_device_tokens`.** The
  method of `RefreshTokenStore` has no default body any more (the default
  answered `DeviceTokenRevocation::Unsupported`, so a store compiled and left
  a lost device's tokens usable). Implement it to revoke the device's tokens in
  one statement, or return `Ok(DeviceTokenRevocation::Unsupported)` to say
  plainly that the store cannot.
- **`no method named user_id found for enum AuthState`.** Rename to
  `pending_user_id` where you drive a login or attribute an audit line (it
  still answers for `Identifying`, `Authenticating` and `PendingWorkflow`, so
  it is not a principal). Where you need the authenticated user, as a
  principal or to match a device to its owner, call the new
  `authenticated_user_id`, which answers only for `Authenticated`.
  `AuthSession::user_id` is unchanged.
- **`StoredTenantOAuthProviders::new(store)` takes a second argument, the
  cipher.** You will see "this function takes 1 argument but 2 arguments
  were supplied" on the new call, or "no method named `with_cipher`" on the
  old one. Pass the `Arc<FactorSecretCipher>` you already use for OTP
  secrets: `StoredTenantOAuthProviders::new(store, cipher)`. A test or
  development directory with no cipher calls `new_unencrypted(store)`.
- **`AuthzEntityProvider::entities_for_tenant` has no default.** You will see
  "not all trait items implemented, missing: `entities_for_tenant`". Implement
  it to load the principal's roles and the resource for that tenant only. A
  provider that has no tenants answers `None` by calling `entities_for` and
  refuses `Some(tenant)` with an error of its own (the session treats an error
  as a denial), instead of answering a tenant's check from data that is not
  scoped to it.
- **`AuthzStore::new` is `AuthzStore::try_new`, which returns a `Result`.**
  You will see "no function or associated item named `new` found for struct
  `AuthzStore`". `try_new(evaluator, provider, namespace)?` runs
  `validate()` for you and fails at startup when the provider's entity types
  do not match the schema. A deliberately mismatched store (a test of the
  mismatch) calls `new_unvalidated`, which has the old signature and
  validates nothing; an evaluator with no schema, such as
  `MockPolicyEvaluator`, validates nothing either way.
- **`axess::authz::require` takes a fourth argument, the Cedar `Context`.**
  You will see "this function takes 3 arguments but 4 arguments were
  supplied" on the old call. Pass the context your policies read
  (`context.mfa_verified` and similar); `Context::empty()` is the old
  behaviour and is right only when no policy reads `context`. With an empty
  context a rule that requires an attribute denies every request, and one
  that permits when `context has` the attribute is absent allows every one.
- **`SessionRegistryHandle::active_sessions` and `AuthnService::active_sessions`
  can fail.** The handle method returns `Result<Vec<SessionId>, RevocationError>`
  and the service method `Result<_, ActiveSessionsError>` (`NoRegistry` or
  `Registry`); both used to answer an empty list when the registry could not
  answer. You will see "expected `Vec<SessionId>`, found `Result<..>`": add
  `?` or handle the error. A caller that enforces a limit or revokes on the
  list now stops on an outage instead of acting on "none". The concurrent
  session limit already refused the login on such an outage.
- **`AuthSession::set_authenticated` is private, and `refresh_session`,
  `refresh_session_in_tenant` and `refresh_session_with_device_check` are
  gone.** You will see "method `set_authenticated` is private" (E0624) or
  "cannot find function `refresh_session`". Sign users in through
  `AuthnService`; a test that needs an authenticated session imports
  `axess::testing::AuthSessionTestExt` (feature `testing`) and calls the same
  method name. Replace a refresh with
  `Refresh::new(plaintext, &tenant, |user_id| async move { /* may this account
  still log in? */ }).device_info(info).device_store(&devices)
  .run(&store, &config, &rng, now).await`; the status predicate is what the
  removed forms skipped. The deprecated `refresh_session_with_status_check`
  and `refresh_session_with_status_check_in_tenant` (with `RefreshScope`) are
  removed too; `Refresh::new` with `device_info` replaces each.

- **`complete_signup` takes the verification secret**, and `SignupOutcome::Started`
  carries it: `Started(Option<SignupVerification>)`. You will see "this
  function takes 2 arguments" at `complete_signup(&session)` and "expected
  unit variant" where you match `SignupOutcome::Started`. Match
  `Started(Some(verification))`, mail `verification.secret()` to the address
  (it is shown once; the session keeps a digest), and call
  `complete_signup(&session, secret)` when the person returns with it. A
  taken identifier answers `Started(None)`: send nothing. A wrong secret, an
  expired one (24 hours; `with_signup_verification_ttl`) or a pending signup
  begun before the upgrade answers `AuthnError::InvalidAssertion`; the
  session submits the signup again for a new secret. `WorkflowState` gains
  `verification_digest` and `verification_expires_at`; build it with
  `WorkflowState::new` and `with_verification`.

- **Social login mints and checks its own state.** `SocialProvider::build_auth_url()`
  takes no argument and returns `AuthUrl { url, state, pkce_verifier }`: you
  will see "this method takes 0 arguments" where you passed a state, and "no
  field `state`" nowhere (it is new). `mint_csrf_state` is private.
  `exchange_code(expected_state, returned_state, code, pkce_verifier)` compares
  the stored and the echoed state in constant time and answers
  `SocialError::StateMismatch` (also for an empty expected state), and with
  PKCE on answers `SocialError::InvalidPkceVerifier` for a verifier under 43
  characters, both before any request. Match the two new `SocialError`
  variants. `with_http_client(client)` is gone: use
  `with_http_client_builder(|builder| builder.user_agent(..))`, which returns
  `Result` and always applies the no-redirect policy and the 30 s timeout last.
- **`AuthUrlResult` is a struct**, not the tuple `(Url, String, String,
  String)`: you will see "expected struct `AuthUrlResult`, found tuple" in an
  `OAuthProvider` implementation and "no field `0`" in a caller. Build and read
  `AuthUrlResult { url, csrf_state, nonce, pkce_verifier }`.
- **`OAuthProvider::fetch_userinfo` and `refresh_token` check `sub`.** They
  take the expected subject (`fetch_userinfo(access_token, expected_subject,
  dpop)`, `refresh_token(refresh_token, expected_subject, original_nonce,
  dpop)`), so a caller of the old forms sees "this method takes 2 arguments".
  The `_for_subject` twins are gone (they are these methods now). The forms
  that do not check are `fetch_userinfo_unchecked` and
  `refresh_token_unchecked`, which an `OAuthProvider` implementation now
  implements in place of `fetch_userinfo` and `refresh_token` (you will see
  "not all trait items implemented, missing: `fetch_userinfo_unchecked`"). Call
  the unchecked forms only where the subject is checked by other means.
  `AuthnService::fetch_userinfo` and `refresh_oauth_token` are unchanged.
- **`FrontChannelLogoutHandler::new` returns the session-bound handler**
  (`BoundFrontChannelLogoutHandler`), and `with_session_match_required` is gone.
  Mount `BoundFrontChannelLogoutHandler::handle_frontchannel_logout` behind the
  session layer. The unbound handler is `FrontChannelLogoutHandler::new_unbound`
  (anyone who holds an `iss` and `sid` ends that session, and `SameSite` does
  not protect it); keep the route on `FrontChannelLogoutHandler::
  handle_frontchannel_logout` with it.
- **`Refresh::new` takes the tenant.** `Refresh::new(&plaintext, &tenant,
  status_check)`; you will see "this function takes 2 arguments but 3 were
  supplied" the other way round, at every `Refresh::new(&plaintext,
  status_check)`. `in_tenant` is gone, since the tenant is no longer optional.
  A route that really serves every tenant calls `Refresh::any_tenant(&plaintext,
  status_check)`, which does not compare the token's tenant with the request's.
- **`WorkloadResolver` and `MtlsResolver` take a slug-to-tenant lookup.** The
  third argument of `WorkloadResolver::new`, `MtlsResolver::new` and
  `MtlsResolver::from_chain` is `impl Fn(&str) -> Option<TenantId> + Send +
  Sync + 'static` in place of a `TenantId` (you will see "expected an
  `Fn(&str)` closure, found `TenantId`"). The resolver calls it on the slug of
  the verified claims or the parsed certificate and answers
  `IdentityError::NotAuthenticated` when it returns `None`. The registry is
  your cached map; `peek_spiffe` stays for logging.
- **`WorkloadMapping` no longer has `workload_id`**, and the example mappers
  (`github_actions_mapper`, `gitlab_mapper`, `k8s_sa_mapper`,
  `k8s_sa_mapper_pinned`) no longer take a trust domain. The resolver builds
  the `WorkloadId` from its own trust domain and the mapped `service_name` and
  `tenant_slug`, so the trust-domain pin is a real check and a mapper cannot
  name another domain. Remove the field and the `WorkloadId::build` call from
  your mapper.
- **`ServiceSigner::sign_for` takes the request's headers.** `sign_for(audience,
  unix_seconds, method, target, &headers, body)`: you will see "this method
  takes 6 arguments but 5 were supplied". Pass the header map that goes out
  (an empty `HeaderMap` when the request sends neither `Content-Type` nor
  `Content-Encoding`); send those two headers exactly as signed. The value now
  carries `v3=` beside `v2=`.

### Stored values

Sessions and audit events written by 0.15.0 (a plain list of kinds) still
load, with no flag and no cutoff. A session reads each factor as verified at
its `authn_time`, the only time the row knew (an in-flight `Authenticating`
row, which has none, reads them as the Unix epoch, so no freshness check
passes); an event reads each at its `event_time`. Every write is the new form.
A 0.15.0 binary cannot read a row the new form wrote, so finish the rollout
before relying on a rollback.

### Behaviour

- **A wrong guess is followed by a delay.** Consecutive wrong guesses from
  one client address at one account are refused for one second after the
  first, doubling to sixty-four, as `FactorOutcome::Throttled { retry_after }`
  (`AuthnError::Throttled` from `prepare_factor`; 429 with `Retry-After`
  under `default-error-response`); a right guess clears it, a known device is
  not throttled, and the per-account lock still caps everything. Without
  `client_ip::layer` the delay is per account for every address and the
  service logs an error once. `LockoutPolicy::without_throttle()` is the
  opt-out.

- **A revoked session is ended on every route.** With the registry given to
  `SessionLayer::new`, an authenticated session the registry no longer holds
  is deleted from the store and the request runs as a new guest, whatever
  guards the route. It costs one registry call per authenticated request. A
  session that was authenticated without being registered (a test that calls
  `set_authenticated` directly) is ended too: register it, or build the layer
  with `without_registry_insecure`.
- **A session ends 7 days after it authenticated, and an impersonation after
  1 hour, however active it is.** The defaults used to be no cap, so a session
  in use lived as long as the cookie did. Users sign in again once a week; an
  administrator impersonates afresh each hour. To keep the old behaviour build
  the layer with `.with_max_session_age(None)` and
  `.with_max_impersonation_age(None)` (or set `None` on the config builder), or
  pick other ages with `Some(..)`.
- **A refresh family ends 90 days after the login it descends from.**
  `RefreshTokenConfig::default()` used to set no `max_lifetime`, so a family
  refreshed at least once per `ttl` never expired. A client that stayed signed
  in for longer signs in again at day 90. To keep sliding expiry only, use
  `.with_max_lifetime(None)`; for another cap, `Some(..)` (at least `ttl`).
- **A `device_info` without a `hash_pepper` is refused.** Issuing or refreshing
  with a device string on a config with no pepper returns
  `RefreshError::InvalidConfig("device_info needs a hash_pepper ..")`; the
  unkeyed digest let a reader of the store confirm a guessed device string.
  Set `hash_pepper`. To move a deployment that has been running without one
  without losing a token, set `hash_pepper` to the new secret and
  `previous_hash_pepper: Some(PreviousPepper::Unkeyed)`, then clear the
  previous pepper after one `ttl`. To keep unkeyed digests on purpose, call
  `.allow_unkeyed_hashes()` on the config.
- **The concurrent-session cap fails closed.** With `max_sessions_per_user`
  set, a login whose registry cannot list the user's sessions is refused.
- **A service built without a breached-password check logs a warning once at
  `build`,** and nothing else changes: no password is screened. With
  `with_breached_password_check(check)` on the builder, `complete_password_reset`
  refuses a password the check knows (`Ok(false)`, audit reason
  `password_breached`) and, by default, one the check could not screen
  (`breach_check_unavailable`), leaving the reset link usable; your own
  signup, change and enrolment forms get the same through
  `AuthnService::check_chosen_password` and `hash_chosen_password`. To admit
  an unscreened password during an outage of the check, call
  `allow_unchecked_when_breach_check_unavailable()` on the builder; to exempt a
  tenant, set its `PasswordRules::breached_check` to `false`.
- **`ValkeySessionRegistry` takes scores and cutoffs from the server's clock**
  (`TIME`), and `invalidate_user` and `invalidate_session` return an error when
  the revocation publish fails.

- **`FactorSecretCipher` refuses the first release's binding by default.** A
  factor secret or tenant OAuth credential still sealed the 0.14.0 way no
  longer opens, so the user's login (or the tenant's SSO) fails with a
  secret that cannot be opened. If rows may still be in that binding, run the
  cipher with `.with_first_binding(LegacyBlobs::AcceptUntil(cutoff))` until
  they have moved (each is re-sealed by the login or first use that opens it),
  then drop the line.
- **A service with no factor-secret cipher refuses to store a TOTP or HOTP
  secret.** A login that verifies a one-time code writes the row back (the
  replay step or the counter); with no cipher that write now fails with
  `AuthnError::Internal` naming `allow_plaintext_factor_secrets`, and the row
  is left as it was. Set `with_factor_secret_cipher` (the production answer;
  the next login seals a plain secret). A test or development service that
  keeps secrets in plain text calls `allow_plaintext_factor_secrets()`, which
  is not for production.
- **A `JwtVerifier` with no issuer pin refuses every token.** `verify` answers
  `JwtError::VerificationFailed` ("no issuer is pinned"), the way it already
  did for a missing audience. Add `.with_issuer("...")`, or
  `.allow_any_issuer()` where the key set is yours alone.
- **`verify_jwt` refuses a `ValidationConfig` that pins no audience or no
  issuer.** `ValidationConfig::new()` and `::default()` pin neither, so a
  direct caller sees the same `VerificationFailed`. Set `audience` and
  `issuer`, or set `allow_any_audience` and `allow_any_issuer` to `true`.
  A `ValidationConfig { .. }` literal needs the two new fields or
  `..ValidationConfig::new()`.
- **`require_authz!` warns when no request-context provider is installed.**
  The first request through a gate whose store has a policy that mentions
  `context`, with no `Extension<Arc<dyn RequestContextProvider>>`, logs a
  `tracing` warning (once per gate). Decisions are unchanged: the check still
  runs on an empty context. Install the provider to silence it.
- **A new `AuthnServiceBuilder` refuses a second password-reset request for
  an identifier inside 60 seconds.** `begin_password_reset` answers `Ok(None)`,
  as for an unknown identifier, so a test or a script that resets one account
  twice in a row gets no token the second time. Call
  `without_password_reset_cooldown()` to restore the old behaviour, or
  `with_password_reset_cooldown(d)` to pick the window. The record is per
  process.
- **`PasswordRules::default().history_count` is 5, not 0.** A reset to one of
  the last five passwords is refused with `Ok(false)`, and a rules value
  deserialized without the field gets 5. Rules you set explicitly are
  unchanged; set `history_count: 0` to keep history checking off. The
  password check has no breached-password hook.

- **A rate limiter whose prerequisite is missing answers 500.** A
  `LoginIdentifier`, `UserId` or `TenantId` limiter on a request without its
  `RateLimit*` extension, and a `PeerIp` limiter on a request with no peer
  address (the server was not built with
  `into_make_service_with_connect_info`), now answer `500 Internal Server
  Error` and log one error (at most once a minute, once a second for the peer
  case) instead of limiting per peer or sharing one `ip:unknown` bucket. Put
  the layer that inserts the extension outside the limiter, or serve with
  connect info. `RateLimitConfig::builder().allow_shared_bucket()` restores the
  0.16.0 behaviour. `RateLimitConfig` has a new public field
  `allow_shared_bucket`; struct literals add it. `ClientIp` is unchanged.
- **A token-exchange response without `issued_token_type` is refused.**
  `TokenExchangeClient::exchange` answers `DelegatedError::MalformedResponse`
  (RFC 8693 section 2.2.1 requires the member) instead of reading the token as
  an access token. An authorization server that omits it needs to send it.
- **`SessionLayer` refuses a cross-site WebSocket upgrade.** Every upgrade
  (`Upgrade: websocket`) is checked before the session is read: with
  `with_websocket_origins([..])` its `Origin` must be listed, and without it
  the `Origin` must be the request's own `Host` under `https` (`http` or
  `https` when the cookies are not `Secure`); an upgrade with no `Origin`
  passes the host rule. A refused upgrade answers `403` and no handler runs.
  You will see this if a page on one host opens a socket on another, or a
  proxy rewrites `Host`: name the page's origin with `with_websocket_origins`.
  The `CsrfLayer` check is unchanged. `SessionService` now needs a response
  body that is `Default` (`axum::body::Body` is).
- **Signed requests are `v3`, and `v2` is refused by default.** A
  `ServiceSecretLayer::signed` route reads the `v3` signature, which also covers
  `Content-Type` and `Content-Encoding`, and refuses a header that carries only
  `v2`. A caller that still sends `v2` alone is answered `401`; move it to the
  new `sign_for` (which sends both), or set
  `SignedRequests::accept_v2_until(instant)` for the migration window. The
  default `max_body_bytes` is 256 KiB (it was 1 MiB): a signed route that takes
  larger bodies sets `max_body_bytes` itself. Cap the concurrency of every
  signed route (a `tower` `ConcurrencyLimitLayer` outside the layer): the body
  is buffered before the secret is checked.
- **`TraceContextLayer` ignores an inbound `traceparent`.** Every request now
  starts a new trace, because the header is the caller's claim (its trace id
  can collide with or poison another trace, its sampled flag can force sampling
  of every request). A service behind an edge that vets the header, which
  should join its caller's trace, calls `TraceContextLayer::new().trust_inbound(true)`.
- **A locked account's own devices can still log in.** Build the service with
  `AuthnServiceBuilder::with_device_store(devices)` and, while the failure
  counter has an account locked, a login from a device the account has used (a
  `Seen` or `Trusted` row of the device store owned by that user, as the session
  layer's device resolver bound it to the session) works; the lock keeps every
  other origin out, as before. Without a device store nothing changes. A wrong
  guess from such a device is still counted, but the account's atomic guess
  reservation does not refuse it, so keep the device cookie as strong as a
  credential. An administrator's suspension is not affected.
- **The one-argument session-store and device-store constructors are
  `plaintext_insecure`.** `SqliteSessionStore::plaintext(pool)`,
  `SqliteDeviceStore::plaintext(pool)` and the Postgres, MySQL and Valkey
  equivalents are renamed, with no alias: the compiler names every call.
  The name says what it does, storing every session (and its user id) or
  device binding unsealed. A production store is `SqliteSessionStore::new(pool,
  SessionCrypto::new(key))` with a key from your secret store; keep
  `plaintext_insecure` for tests and local runs. The device stores' deprecated
  `with_clock`, which did nothing (every method takes its `now`), is removed,
  as is `RevocationAwareSocket::is_revoked`; read `is_closed`.
- **Hash a chosen password with `hash_new_password`.** `generate_password_hash`
  checks nothing, so a signup or enrolment path that called it accepted a
  password over `MAX_PASSWORD_BYTES` (which no login can then verify) and one
  that fails the tenant's rules. `hash_new_password(password, &rules)` refuses
  both with a `NewPasswordError`, then hashes. Nothing breaks if you keep
  calling `generate_password_hash`; switch where a person chose the password.
