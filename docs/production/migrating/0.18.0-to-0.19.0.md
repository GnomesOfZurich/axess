# 0.18.0 to 0.19.0

Compile breaks first: the compiler finds each of them for you. Then the
behaviour changes, which it does not. Then what is new and breaks nothing,
the narrowed dependency features, and last the defaults this release leaves
where they were.

### Compile breaks

- **`Issuer::Custom("label".to_string())`: "mismatched types, expected
  `CustomLabel`, found `String`".** The variant holds a `CustomLabel`, whose
  field is private, so a label that `Issuer::custom` would refuse (a built-in
  issuer's `"oauth"`, a bad format) cannot be written out by hand. Build the
  issuer with the constructor: `Issuer::custom("label")?`. A `match` arm
  `Issuer::Custom(label)` still works; `label.as_str()` is the text.

- **A release build with the `testing` feature on no longer compiles** in
  axess-core, axess-factors, axess-rng and axess-clock; the error names the
  feature. Remove `testing` from the release build, or enable
  `allow-testing-in-release` on `axess` or `axess-core` for a build that
  means it (a benchmark, a release-mode test run). Debug builds are
  unaffected.

- **`axess_core::testing::mock_tracing`, `axess_core::TracingCapture` and
  `axess_core::testing::oauth_wiremock` are gone, and so is the
  `testing-oauth` feature: "unresolved import `axess_core::testing::oauth_wiremock`",
  "unknown feature `testing-oauth`".** The tracing capture and the OIDC
  fixture moved to a new crate, `axess-testing`, that you take as a
  **dev-dependency** (`axess-testing = "0.19"`), so that `wiremock` and the
  `rsa` crate can no longer be pulled into a production build by a feature
  flag. Change `axess_core::testing::mock_tracing::TracingCapture` to
  `axess_testing::mock_tracing::TracingCapture`, and
  `axess_core::testing::oauth_wiremock::{oauth_discovery_document,
  oauth_generate_rsa_keypair, oauth_mount_oidc_endpoints}` to the same names
  under `axess_testing::oauth_wiremock`. `oauth_discover_provider` and
  `oauth_setup_provider` now live in `axess_core::testing::oauth_provider`
  (features `testing` and `oauth`) and take the identity provider's address
  as a `&str`: pass `&server.uri()` where you passed `&server`. Replace the
  `testing-oauth` feature with `testing` and `oauth`.

### Behaviour changes

- **A refresh token issued from a session carries the session's
  authentication time.** `RequestAuthnService::issue_refresh_token` used to
  record no authentication time, so redeeming the token produced a session
  whose `authn_time` was the moment of issue: a session near
  `max_authenticated_age` became a fresh login, and passed every recency
  gate (`Fido2Options::max_authn_age`, step-up freshness). The token now
  carries the session's `authn_time`, the family's `max_lifetime` counts from
  it, and a session rotated from the token keeps it. A session that
  authenticated longer ago than `max_lifetime` is refused with
  `AuthnError::NoFlow`: it authenticates again before it gets a token. The
  free function `issue_refresh_token` is unchanged and anchors at `now`, right
  for the moment of a login; `issue_refresh_token_from_login` is the form that
  takes the authentication time.

- **`login_with_password` never answers `Locked`.** The guess that reached
  the attempt limit, and a request that raced into a lock after
  `begin_login`, used to come back as `FactorOutcome::Locked` (or as an
  `AuthnError::Locked` or `NotActive`), which told a caller who had proved
  nothing that the account exists. They now answer
  `FactorOutcome::InvalidCredential`, as a wrong password does. The audit row
  still records the lockout. A form that wants to show the lock calls
  `begin_login` and `verify_factor` itself.

- **`with_lockout_revealed_on_begin` shows a lockout only.** An administrative
  suspension, a pending verification or a closure answers
  `LoginOutcome::InvalidCredentials` even with the option on; the audit row
  is unchanged.

- **A taken signup identifier rotates the session id too.** With hidden
  conflicts (the default), `begin_signup` for an identifier that has an
  account now regenerates the session id, as a free identifier does, so the
  `Set-Cookie` no longer tells the two apart.

- **The guess throttle keeps building while the lockout counter is down.**
  Under `CounterUnavailable::Allow`, a failed counter write used to skip the
  per-key throttle too; it now records the guess.

- **A password reset works in a tenant whose timed suspension has run out.**
  Both the request and the completion read the tenant's status as of the
  service's clock, as a login does.

- **A refresh device check reads the device store, not its cache.**
  `Refresh::device_store` loads the device with the new
  `DeviceStore::load_fresh`, which `CachedDeviceStore` answers from the
  backing store. A device revoked on another instance stops the next refresh;
  before, it kept refreshing until the cached row expired (60 seconds by
  default). The cost is one backing-store read per refresh where the cache
  used to answer it. Another `DeviceStore` implementation gets `load_fresh`
  as `load` and changes nothing.

- **An administrator cannot impersonate themselves**, and an impersonation
  that fails after the administrator's registry entry was made ends that
  entry. A failed row with the reason `self_impersonation` records the first.

- **A discoverable passkey login that fails at a gate clears its ceremony.**
  A store error before the assertion is verified left the ceremony state in
  the session; it is removed whichever way the call ends.

- **An email code is not sent for a row that changed under it.** When a
  concurrent write changed the factor's address or limits between the claim
  and the store of the code, the request is refused and the claim released,
  where it used to write a stale copy of the row over the change. A change to
  the failure count alone is kept.

- **A TTL set to an extreme value no longer panics.** A huge
  `with_signup_verification_ttl`, `with_unknown_issuer_memory` or refresh
  `ttl` clamps to the latest instant chrono holds. A memory interval past
  chrono's range remembers for as long as chrono can count, where it used to
  remember nothing.

- **A `require_authz!` resource id with two or more placeholders refuses a
  value that holds a separator of the template, and two placeholders with
  nothing between them no longer compile.** `Doc:{$tenant}{id}` is refused
  at compile time ("must put a literal separator between two placeholders"):
  tenant `ab` with id `c1` and tenant `a` with id `bc1` were the same
  resource. Write `Doc:{$tenant}/{id}`. With a separator in place, a request
  whose tenant or path value contains that separator (a path id of `a/b`
  under `{$tenant}/{id}`) is denied as an invalid resource, because it could
  be read as another tenant's id; tenant ids that are UUIDs never contain one.
  A template with a single placeholder is unchanged.

- **The login throttle keys an IPv6 client on its /64 prefix.** Failures from
  any address inside one /64 share one delay, as the request rate limiter
  already counted them. A throttle entry a store holds under a full IPv6
  address is no longer read and ages out; nothing needs migrating. A
  `max_delay` too large to add to the clock now refuses the guess with that
  delay where it used to let the guess run.

- **The Valkey session registry writes a second sorted set,
  `{prefix}:reg-at:{user}`, with each session's registration time, and
  `active_sessions` orders by it.** The set is added beside the existing one
  and expires with it; nodes of the old version ignore it, and a session
  registered before the upgrade is ordered by its last-seen time (its score)
  until it registers again. `max_sessions_per_user` therefore evicts the oldest
  session, not the least recently used one.

- **`spawn_cleanup_task` panics on a zero interval, naming it, where the task
  used to end silently.** The call is at startup, so the panic shows up there;
  pass a non-zero `Duration`.

- **A cookie name with a `__HOST-` or `__SECURE-` prefix in another case is
  held to the rules of the prefix.** `SessionConfig` refuses it with
  `secure(false)` (or, for `__Host-`, a path other than `/`) where it used to
  pass and leave a cookie the browser refuses to store.

- **`FactorStore` gains `claim_fido2_credential` and
  `release_fido2_credential`, both with defaults, so nothing breaks, but the
  guarantee that one passkey credential id belongs to one account needs them.**
  The defaults check `fido2_credential_holder` and write nothing, which keeps
  the race between two registrations that both look before either stores. A
  store of your own implements the claim atomically (a unique index on
  `(tenant_id, credential_id)` and one conditional insert) and the release
  (delete the user's own claim). The SQLite example adds a migration for its
  `fido2_credential_claims` table; copy it with the two methods.

- **A cookie name in `CsrfConfig` with a `__HOST-` or `__SECURE-` prefix in
  another case is held to the rules of the prefix,** like the session cookie.

- **A screened client no longer follows `HTTP_PROXY`, `HTTPS_PROXY` or
  `ALL_PROXY`: the request to an identity provider fails to connect from a
  host that reaches the network only through a proxy.** A proxy resolves the
  target's name itself, so the connect-time address screen never saw where it
  connected. `EgressPolicy::screened()` and
  `screened_allowing_loopback_http()` now build a client with no proxy.
  Either reach the identity provider directly, or name the opt-out
  `EgressPolicy::unscreened()`, which follows the environment as before, and
  filter at the proxy.

- **The example applications set shorter sessions: 15 minutes idle and 10
  hours in all.** The library defaults have not moved (24 hours idle, 7 days
  in all), so an application that depends on `axess` alone sees nothing. An
  application that began as a copy of the minimal, sqlite, OAuth or FAPI
  example carries the old values, and gets the new ones by copying the two
  named constants `STRICT_IDLE_TTL` and `STRICT_MAX_SESSION_AGE` and the two
  builder calls that use them, `SessionLayer::with_ttl` and
  `SessionLayer::with_max_session_age`. Users of the example then sign in
  again after 15 idle minutes and after 10 hours whatever they were doing;
  raise the constants if that is too short for your product.

- **The examples that were copied for their handlers behave differently in
  five places a copy should take over:** the OAuth example's callback refuses
  an answer on another provider's path than the login began with, and its
  refresh takes the stored token out of the session so concurrent refreshes
  present it once; the FAPI example creates a local user only for a verified
  e-mail address; the minimal example spends a password check before every
  early refusal of a login; the sqlite example gives each sensitive form its
  own rate-limit bucket and sends a login that needs a further factor to that
  factor's page.

- **The egress screen refuses more addresses: a tenant issuer at `198.18.x.x`,
  `192.0.2.x`, `240.x.x.x` or a NAT64 form of a private address is now
  `private`.** An IPv6 address that carries an IPv4 address (NAT64
  `64:ff9b::/96`, `64:ff9b:1::/48`, 6to4 `2002::/16`, IPv4-compatible
  `::a.b.c.d`) is judged as the IPv4 address it carries, and the IANA
  special-purpose ranges `192.0.0.0/24`, `198.18.0.0/15`, `240.0.0.0/4` and
  the three documentation ranges are refused with the name `private`. An
  identity provider that sits in one of them needs `EgressPolicy::unscreened()`.

- **`DiscoveryDocument::fetch` and `Discovery::fetch` refuse a private,
  loopback or metadata issuer: `OidcError::EgressRefused` where 0.18.0
  fetched it.** Both used to apply only the HTTPS rule. They now apply
  `EgressPolicy::screened()` to the issuer URL and to every URL the document
  names, `jwks_uri` included. An identity provider on the deployment's own
  network (or a mock on loopback in a test) is reached with the named
  opt-out: `DiscoveryDocument::fetch_screened(url, &client,
  EgressPolicy::unscreened())`, or the new `Discovery::fetch_screened`.

- **A signed service request that repeats an accepted one is answered `401`
  even under another scheme or with another signed header.** The replay cache
  remembers the caller, the stamp, the method, the target and the body of an
  accepted request, where it remembered the tag it arrived with. A caller that
  retries the identical request within the same second is refused the second
  time, as before; a caller that sends the same body to the same target in
  the same second with a different `content-type` now collides too, so stamp
  each request with the second it is made in, or change the body.

- **`StoredTenantOAuthProviders::upsert` refuses a second tenant's record with
  an issuer and client id another tenant holds: `OAuthError::Config`, "already
  registered by another tenant".** Two tenants with the same client at one
  issuer made every back-channel logout token for that client ambiguous and
  refused (`400`), so a tenant administrator could end another tenant's
  IdP-initiated logout by registering its pair. Give each tenant its own
  client at the IdP. Name the pairs the global registration holds with
  `with_global_registration(issuer, client_id)` on the directory so a tenant
  cannot take those either. A record already in the store with a colliding
  pair is not removed: the logout route now lets the global registration
  decide such a token, and two tenants' records stay ambiguous until one is
  removed.

- **`begin_grant` refuses a `DelegatedProvider` whose `authorization_endpoint`
  is plain HTTP to a remote host: `DelegatedError::Transport`, "must be
  https".** Only the token endpoint was checked, at `complete_grant`. HTTP to
  `localhost`, `127.0.0.1` and `[::1]` is still accepted for a local IdP.

- **`SocialProvider::new` refuses an `http://` `redirect_uri` to a remote host
  (`SocialError::Config`), and `exchange_code` refuses a token response with
  no `token_type` or one that is not `Bearer`
  (`SocialError::InvalidResponse`).** The authorization code returns to the
  redirect URI, so it must be HTTPS (HTTP to `localhost`, `127.0.0.1` and
  `[::1]` stays). `token_type` is required by RFC 6749 section 5.1 and the
  token is sent on as a bearer token; GitHub, Google, Discord and Reddit send
  `bearer` or `Bearer`. A provider that omits `token_type` fails every login until it is
  fixed at the provider or named with `.accept_missing_token_type()`, which
  reads the missing value as `Bearer`; a present value that is not `Bearer`
  is refused either way.

### Added

- `issue_refresh_token_from_login`, `cascade_revoke_by_refresh_family_and_tokens`
  (which also revokes the tokens bound to the devices, where
  `cascade_revoke_by_refresh_family` revokes the devices only),
  `DeviceStore::load_fresh` (a provided method), and
  `AuthnServiceBuilder::with_impersonation_max_authn_age`.

- In `axess_core::testing`: `MockIdentityStore::arm_account_status_failure`
  and `MockFactorStore::arm_concurrent_write_on_lost_swap`. In the new
  `axess-testing` crate: `stall` (a gate and a never-completing future for
  cancellation tests), `durations` (a table of extreme TTL values) and
  `ipv6_forms` (the IPv6 forms that carry an IPv4 address or share a `/64`).

- **`SecurityProfile::Strict`.** `axess_core::profile` names one value for
  each setting a high-assurance deployment tightens, and applies it to
  `SessionConfig`, `RefreshTokenConfig`, `Fido2Options`, `JwtVerifier`, the
  egress policy, `CachedDeviceStore`, `DeviceCookieConfig`, `CsrfConfig`,
  `WatchOptions`, a rate limit and the `AuthnServiceBuilder`. It changes
  nothing until you call it, and `SecurityProfile::Standard` is today's
  defaults as the same values. See `production/strict-profile.md`.

- **`AuthnServiceBuilder::with_argon2_cost`** sets the Argon2id cost of new
  password hashes (default `Argon2Cost::default()`, the 19 MiB, two-pass cost
  the library has always used); a login rehashes a stored hash made under
  another cost. **`with_password_reset_ttl`**, **`with_max_password_reset_ttl`**
  and `begin_password_reset_with_default_ttl` give a reset token a configured
  lifetime and a cap (default: no configured lifetime, a cap of seven days, as
  before). **`with_impersonation_max_authn_age`** refuses
  `begin_impersonation` for an administrator whose authentication is older
  (default: no limit, as before).

- **`DeviceCookieConfig::max_age`, `CachedDeviceStore::ttl` and
  `JwtVerifier::clock_skew`** read back what the matching setter set.

### Dependencies

- **`axess-core` no longer enables tokio `full` or `rt-multi-thread`.** It asks
  for `macros`, `rt`, `sync` and `time`; an application that relied on
  axess-core to enable another tokio feature (`net`, `fs`, `io-util`,
  `rt-multi-thread`) names it in its own `Cargo.toml`.

- **`sqlx` is taken without default features.** `any`, `migrate`, `json` and
  the `macros` proc-macro crate are not enabled by axess-core; an application
  that used `sqlx::migrate!` or `sqlx::any` through axess-core enables them in
  its own `Cargo.toml`.

- **`chrono` is taken without default features.** `clock` stays on through
  `axess-clock`; an application that names `chrono` itself and calls
  `Utc::now()` enables `clock` in its own `Cargo.toml`.

- **`fred` is taken without `transactions`, `replicas` and `i-cluster`.** An
  application that shares the dependency and calls those APIs enables them in
  its own `Cargo.toml`.

### Decisions left as they are

- **`Fido2Options::max_authn_age` is still `None`.** The mechanism is in
  place and a deployment sets it (`Some(Duration::from_secs(300))` is the
  usual choice); the default is a decision for the maintainers.

- **`CachedDeviceStore` still defaults to a 60 second TTL.** The refresh
  device check no longer depends on it; a cached `load` still does.
