# 0.2.0 to 0.2.1

`v0.2.1` is a patch release. The only behavioural change is a
CSRF hardening: the double-submit token now binds to the session
id (`HMAC(signing_key, nonce || session_id)`) rather than to the
signing key alone, and `CsrfLayer` fails closed with 403 when the
session-id extension is missing on a state-changing request. This has two
adopter-facing consequences:

Place `CsrfLayer` inside the session layer, so that CSRF validation
runs after the session layer and finds the `SessionHandle` request
extension present. In `axum`, later `.layer(...)`
calls wrap earlier ones, so `.layer(csrf).layer(session_layer)`
is the correct order. Stacks that had the layers in the opposite
order silently validated an unbound token before 0.2.1; that order
now returns 403.

A client that caches the CSRF token across a session change (login,
session regeneration) must re-read the token after the change; otherwise
its first state-changing request after the change fails with 403. Tokens
minted under one session id no longer verify against another.
